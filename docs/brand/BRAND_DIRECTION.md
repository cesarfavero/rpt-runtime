# RPT Brand Direction v0

This is the initial visual identity direction for the runtime-facing product layer.

It is not a final brand book. It is the working source of truth for how the brand should feel while the product and runtime are still being shaped.

Reference concept board:

![RPT brand concept](/Users/cesarfavero/Documents/MyPru/rpt-runtime/docs/brand/assets/rpt-dog-brand-concept-v1.png)

## Core Idea

`RPT` is the main brand.

`dog` is the identity layer, not the whole product name.

The dog concept exists because it makes the project memorable, gives room for a mascot and a recognizable visual language, and still fits the product if it is treated as:

- precise
- alert
- tracking
- robust
- compact

Not as:

- cute first
- meme first
- cartoon first

The product should feel like a serious systems/runtime tool with a distinct identity, not a generic AI startup and not a joke brand.

## Principles

### 1. Technical before cute

The visual system must communicate runtime, systems, compactness, and precision before it communicates mascot energy.

### 2. Memorable without losing credibility

The dog theme should make the brand easier to remember, but never weaken trust in the engineering.

### 3. Ternary language is structural, not decorative

The identity should borrow from:

- `-1 / 0 / +1`
- triads
- blocks
- packed grids
- compressed signals

These should appear as formal structure, not random ornament.

### 4. Runtime personality, not research-paper personality

The product-facing layer should look executable and operational. The research repository can remain neutral and documentary.

## Brand Tone

The tone should be:

- direct
- dry
- technical
- confident
- compact
- disciplined

The tone should not be:

- whimsical
- overhyped
- crypto-neon
- soft startup AI
- mascot comedy

## Color Direction

Primary palette:

- graphite / near-black
- bone / off-white
- rust orange
- muted petroleum green

Suggested starter values:

- `#111315` graphite
- `#ECE7DD` bone
- `#B85C38` rust
- `#3E6668` petroleum green
- `#70757A` neutral metal gray

Rationale:

- dark base gives systems/runtime weight
- bone keeps contrast warm, not sterile
- rust gives memorability without startup purple
- petroleum green adds technical restraint

Avoid as primary look:

- purple AI gradients
- electric blue + black cliché
- pastel mascot palette

## Typography Direction

### Titles

Use a condensed or semi-condensed sans with strong vertical rhythm and engineering presence.

Desired traits:

- sharp
- compact
- assertive
- not playful

### Body

Use a clean, neutral sans for readability.

Desired traits:

- practical
- restrained
- not too humanist
- not too soft

### Technical surfaces

Use a mono or quasi-mono for:

- CLI screenshots
- manifests
- runtime specs
- benchmark callouts

The contrast between expressive title type and disciplined mono should be part of the brand.

## Logo Direction

### Brand mark

Primary mark should be `RPT`.

The brand should not depend on the dog illustration to be recognized.

### Secondary symbol

A dog-head or tracking-hound symbol can exist, but it must be:

- angular
- reduced
- geometric
- system-like
- usable at small sizes

It should feel closer to:

- signal
- triangulation
- sentry
- tracking

than to:

- pet brand
- cartoon animal
- mascot sticker

### Geometry cues

The logo system should draw from:

- hard diagonals
- modular blocks
- ternary triplets
- compressed signal marks
- directional lines

## Iconography

Icons should be:

- dense
- simple
- shape-driven
- sharp-cornered or mildly rounded only where necessary

Good icon subjects:

- runtime
- bundle
- model
- install
- pull
- verify
- hash
- manifest
- block/grid/triad

Bad icon subjects:

- cartoon paws
- dog bones
- cute pet gestures
- generic circuit brain
- generic rocket/AI sparkle

## UI Direction

The UI should feel like a runtime and tooling system, not a social app.

Desired characteristics:

- structured grids
- strong alignment
- compact spacing logic
- high contrast
- panel-based layouts
- terminal references used with restraint
- benchmark cards and manifests treated as first-class visual elements

The UI should support:

- CLI-first product story
- install/run/doctor flows
- model bundle inspection
- runtime diagnostics
- benchmark credibility

Visual references to emphasize:

- bundle manifests
- hashes
- model paths
- installed model registry
- runtime backend selection

## Correct Usage

Correct:

- `RPT` as the primary product signature
- dog symbolism used as secondary identity reinforcement
- ternary-inspired block language in backgrounds, dividers, and badges
- runtime/systems visual texture
- a small number of strong colors
- mono type where technical trust matters

## Incorrect Usage

Incorrect:

- making the mascot the whole brand
- using a smiling/cute cartoon dog as the default mark
- leaning into humor over engineering
- purple-on-white generic AI landing pages
- overusing gradients and glow
- using ternary motifs randomly with no structural meaning
- making the brand look like a toy rather than a runtime system
